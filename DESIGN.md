# Архитектурные решения (DESIGN.md)

## 1. Алгоритмическая сложность (Big O)

### `mapCountryResponse(raw: RawCountry): Country`

- **Временная сложность (Time Complexity):** $O(L + C + B)$, где:
  - $L$ — количество официальных языков в массиве `raw.languages`;
  - $C$ — количество валют в массиве `raw.currencies`;
  - $B$ — количество граничащих государств в массиве `raw.borders`.
  - Для одного объекта страны все операции (обращение к полям по ключу за $O(1)$ и линейные проходы `.map()` / `.filter()` / поверхностное копирование массивов) выполняются за линейное время относительно размера вложенных коллекций. Поскольку для любой страны на практике $L, C, B$ ограничены малыми константами ($< 30$), обработка одного DTO амортизированно выполняется за $O(1)$.
  - При маппинге списка из $N$ найденных стран (`countries.map(mapCountryResponse)`) общая временная сложность составляет $O(N \cdot K)$, где $K = \max(L + C + B)$, то есть $O(N)$ по числу элементов ответа.
- **Пространственная сложность (Space Complexity):** $O(L + C + B)$ на один объект (выделение памяти под новые массивы `languages`, `currencies` и копию `borders` для сохранения иммутабельности исходного DTO) и $O(N)$ для всего списка результатов.

## 2. Выбор задержки `debounce`

Для отложенного запуска запроса при вводе текста выбрана задержка **300 мс**.

- **Если убрать задержку (`0 мс`):** приложение будет отправлять сетевой запрос на каждый введённый символ по мере печати. При вводе слова из 6–8 букв это создаст серию из 6–8 запросов подряд, большинство из которых устареет ещё до завершения сетевого обмена и создаст лишнюю нагрузку на сеть.
- **Если сильно увеличить задержку (например, до `1000–1500 мс` и более):** поиск будет работать с заметной паузой — после завершения ввода пользователю придётся ждать более секунды, прежде чем начнётся загрузка результатов.
- **Почему 300 мс:** эта задержка перекрывает стандартную паузу между нажатиями клавиш при непрерывном наборе слова, благодаря чему промежуточные запросы не уходят в сеть, но при этом поиск начинается практически сразу после остановки ввода.

## 3. Отмена устаревших запросов (`AbortController` vs флаг актуальности)

В модулях `src/core/createSearchController.ts` и `src/core/searchWithTimeout.ts` для защиты от гонки устаревших ответов используется `AbortController` совместно с `AbortSignal.any` и `AbortSignal.timeout`.

- **Почему одного флага актуальности недостаточно:** флаг (например, сравнение счётчика `requestSequence` или `isCurrent`) лишь отбрасывает уже полученный ответ в обработчике `.then()` / `await`, но не прерывает само сетевое соединение. Устаревший HTTP-запрос продолжает занимать слот в пуле соединений браузера, расходовать трафик и дочитывать тело ответа (`response.json()`).
- **Как работает `AbortController` в проекте:** при каждом новом вводе в `handleInput` немедленно (ещё до срабатывания `debounce`) вызывается `activeAbortController.abort()`. Это прерывает активный `fetch` на уровне браузера и освобождает сетевой ресурс. Дополнительно сигнал внешней отмены объединяется с `AbortSignal.timeout(5000)` через `AbortSignal.any`, что позволяет в `classifySearchError` точно разделить ручную отмену (`AbortError`, без вывода ошибки пользователю) и превышение времени ожидания (`TimeoutError`, с показом сообщения и кнопки «Повторить»).

## 4. Алгоритмическая сложность кэша и дедупликации (Big O)

- **Кэш результатов (`Map<string, Country[]>` в `createSearchController.ts`):**
  - **Поиск по ключу (`cache.has` / `cache.get`):** $O(1)$ в среднем по времени, так как используется хеш-таблица `Map` с нормализованным ключом `query.trim().toLowerCase()`.
  - **Запись (`cache.set`):** $O(1)$ в среднем.
  - **Пространственная сложность:** $O(U \cdot M)$, где $U$ — число уникальных поисковых запросов в сессии, $M$ — среднее число стран в ответе.
- **Дедупликация активных запросов (`inFlight: Map<string, InFlightRequest>`):**
  - Проверка наличия уже выполняющегося идентичного запроса и регистрация подписчика выполняются за $O(1)$ в среднем.
